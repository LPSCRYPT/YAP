# Boswell — data architecture research

Researched: 2026-11-03.

Evidence: public source and documentation inspection only. No hardware, authenticated service, model-quality, security, or runtime validation was performed. Implementation claims describe inspected code, not confirmed production deployment. Branch links may change.

**README:** https://github.com/leakydata/boswell#readme

**Capture/transcript/storage:** Host archive retains WAV plus human-readable transcript JSON under data/transcripts and capture-time sidecars under data/times/<clip>.wav.json. Common segment shape is {start,end,text,speaker,words:[{word,start,end,score,...}]}; resolved speaker names/map and sound tags supplement transcripts. Cloud adapter explicitly maps into this same WhisperX-compatible shape: https://github.com/leakydata/boswell/blob/main/web/asr_deepgram.py#L36-L100 . Capture metadata distinguishes actual started time, time_known and device_id from file modification time. `index.db` is explicitly disposable/rebuildable, not source of truth: clips metadata plus FTS5 segments(clip,start,end,speaker,text), porter/unicode61 tokenizer. https://github.com/leakydata/boswell/blob/main/web/index_db.py#L1-L126 .

**Identity storage:** Current speakers.db has people and individual voiceprint rows with person_id, vector BLOB/dimension, speech duration, source clip/diarizer speaker; unknown recurrent voices are people rows with null name. Identity matching retains separate references, rather than averaging to one centroid. Legacy speakers.npz/json exists for migration; don't report it as the current matching database. https://github.com/leakydata/boswell/blob/main/web/speaker_store.py#L1-L60 and #L154 onward; https://github.com/leakydata/boswell/blob/main/web/pipeline.py#L29-L76 .

**Post-transcription:** Local WhisperX alignment + diarization/identity, sound tagging, consolidation, then conversation-level agent review. Current automatic runner batches speech until conversation end, default idle 330 seconds (after speaker consolidation), max wait 900 seconds, minimum 120 characters; it retrieves existing memories for deduplication/context (12 items, min score .55, query prefix 2,000 chars). https://github.com/leakydata/boswell/blob/main/web/agent_runner.py#L1-L180 . This current runner is more relevant than the older standalone host/agent.py.

**Extracted records:** Authoritative separate JSONL files data/agent/{tasks,events,notes,facts,topics,media}. Common metadata _id, _recorded_at, _clips. Fact={subject,fact,said_by}; task={text,due,owner,said_by}; event={title,start,end,said_by,attendees}; note={title,body,said_by,tags}; media note={title,body,source,tags}. https://github.com/leakydata/boswell/blob/main/host/tools_impl.py#L211-L342 . Classified named speaker attribution is required for personal facts/tasks/events/notes; media/unclassified/unresolved diarizer identities are rejected. Important nuance: inspected attribution helper is best-effort when underlying identity/transcript reads fail, so this is not a formally fail-closed evidence policy. MCP README says writers require source clips; lower-level writer attaches context clips when supplied. Merging combines source clips and increments _merged, edits/deletes rewrite JSONL atomically under shared file lock; despite module wording, store is not strictly immutable append-only. reviews.jsonl tracks every covered clip, avoiding duplicate reviews when conversations regroup.

**Retrieval:** (1) SQLite FTS5 exact/keyword transcript retrieval. (2) semantic.db `seg` stores clip/index/start/text/speaker/vector and `mem` stores item_id/kind/subject/text/recorded_at/vector; optional sqlite-vec vec0 tables use cosine distance. Embeddings are local Ollama nomic-embed-text, 768 dimensions; line indexing skips <25 chars. https://github.com/leakydata/boswell/blob/main/web/semantic.py#L1-L169 . (3) `unit` stitches speech across clip boundaries, indexed with first clip/index, conversation, subject section, at/until/time_known, speaker/name/device_id, all contributing clips, sound context, lines/words/text/vector. It is a derived whole-rebuild index alongside the line index, not graph memory: https://github.com/leakydata/boswell/blob/main/web/units.py#L1-L90 . Semantic duplicate clustering exists for same-kind extracted artifacts. MCP/CLI expose search, semantic search, search_units, get_conversation/get_clip, people and record writers (README). This supports retrieval-augmented agents; no general graph query/traversal or bitemporal knowledge truth-maintenance schema was established.

**Privacy/deployment:** Default self-hosted/local ASR + diarization + Ollama inference/embedding; initial models/tokens may require downloads/access. Current cloud support contradicts the README headline 'No audio ever leaves': optional OpenAI whisper-1 uploads audio, Deepgram nova-3 uploads audio+does diarization, identity vectors remain local; optional OpenAI/OpenRouter/Anthropic agent backends send transcripts. Verified adapter code: https://github.com/leakydata/boswell/blob/main/web/asr_deepgram.py and https://github.com/leakydata/boswell/blob/main/web/llm.py#L1-L58 . README also contains an older paragraph claiming keys are only placeholders; actual adapters are stronger evidence of implemented options. Presence of adapter code does not prove external models/endpoints work today. Core archive is usable without cloud, but don't equate that with an unconditional no-egress guarantee.

**Maturity/unknowns:** Richest implementation of these three, including local web server, MCP/CLI and several test files; still small, experimental personal-archive project (observed 1 star/0 forks), not established production service. README reports GPU/CPU measurements and source comments discuss archive-specific evaluations; those are project-author measurements, not independently reproduced benchmarks. Heavy local inference resource requirements are material. Security posture, scale/retrieval accuracy, production reliability, and external endpoint compatibility not verified.
