# OpenPendant — data architecture research

Researched: 2026-11-03.

Evidence: public source and documentation inspection only. No hardware, authenticated service, model-quality, security, or runtime validation was performed. Implementation claims describe inspected code, not confirmed production deployment. Branch links may change.

**README:** https://github.com/adirsingh96/open-pendant#readme

**Capture and transcript model (source verified):** `openpendant.db`, SQLite via sqflite, schema version 13. `clips` has text ID, started_at, duration_s, full_text, wav_path, stt_model, status, session_id, seq; billing/token/refinement-cost fields; alternate STT text/model/error/segments JSON; unique nullable pendant_clip_id for offline import deduplication. `segments` has integer ID, clip_id FK, relative start_s/end_s, absolute spoken_at, text, raw_text and optional speaker. This preserves raw alongside edited transcript text rather than treating a summary as the only record. SQL schema/search: https://github.com/adirsingh96/open-pendant/blob/master/app/lib/db/clip_store.dart#L28-L180 . Capture described in README: 16-kHz PCM over BLE, offline PCM on SD synced to host; meetings group chunks as one transcript, and current meetings explicitly do not apply speaker diarization. A speaker column is not evidence that meeting diarization is active.

**Post-transcription:** OpenAI `chat/completions` cleans turns while preserving indices; `cleanAndRecapDay` processes ≤120 segments in a combined pass and larger days in batches of 80 before recap generation. https://github.com/adirsingh96/open-pendant/blob/master/app/lib/stt/openai_refine.dart#L155-L200 . Daily artifact fields: dayKey, headline, arc, people[], languages[], chapters[{when,title,what}], decisions[], followUps[{owner,action,when}], openLoops[], noise, model, costUsd, updatedAt. https://github.com/adirsingh96/open-pendant/blob/master/app/lib/db/day_recap.dart . README says follow-ups become checkable notes/reminders and daily recap refresh replaces the prior recap. This is structured document/artifact processing, not entity-relation extraction with validity intervals.

**Search/RAG:** Local clip search is SQL `LIKE` across clips.full_text and segments.text, not FTS/vector search (inspected query). Mem0 client uses hosted `api.mem0.ai/v3/memories/add/` and `/search/`. It deletes/replaces a day's previous memories, sends one recap pack with user_id, app_id=openpendant, run_id/day_key, observation_date and `infer:false`. Crucial: custom 'extract durable facts' instructions exist, but this add call explicitly disables inference; do not describe it as verified Mem0 fact extraction or graph construction. Search requests top_k=8, threshold=0, rerank=true and user/app filters. https://github.com/adirsingh96/open-pendant/blob/master/app/lib/mem0/mem0_client.dart#L33-L128 . Active chat UI requires both Mem0 and OpenAI keys; reads all local recaps plus speech since recaps, searches remote Mem0, prefers local copies of a day, calls OpenAI answerFromMemories and saves question/answer/day links. It is not simply top-k retrieval over raw transcript chunks: local recap packs are prepended independently of query ranking. https://github.com/adirsingh96/open-pendant/blob/master/app/lib/ui/memories_page.dart#L194-L312 . Opening Memories with a configured Mem0 key automatically pushes unsynced recaps.

**Privacy/deployment:** Local storage does not mean cloud-free. README offers Saaras v4 cloud or on-device Qwen3-ASR; laptop tools offer local Whisper. Cleanup/recap/answers call OpenAI; configured memory integration sends recaps to hosted Mem0. Mem0 URLs and OpenAI endpoint are hard-coded in inspected clients: no self-hosted memory deployment established. Keys stay on host, not MCU (README). README's 'meeting stays on phone' should be qualified by these explicit external processing paths.

**Maturity/unknowns:** Substantial working-shaped app/firmware code with database migrations, but small DIY project; GitHub metadata observed 0 stars/0 forks and creation 2026-08-18, not adoption evidence. No runtime reliability or retrieval-quality evaluation performed. No implemented local vector store, graph schema, relationship traversal, bitemporal fact history or contradiction-resolution engine established. Mem0's server-side storage engines/graph configuration are unknown from this client and must not be inferred from the Mem0 brand.
