# memrii — data architecture research

Researched: 2026-11-03.

Evidence: public source and documentation inspection only. No hardware, authenticated service, model-quality, security, or runtime validation was performed. Implementation claims describe inspected code, not confirmed production deployment. Branch links may change.

**README:** https://github.com/simplee-labs/memrii#readme

**Scope correction:** README explicitly says upstream Omi cloud sync, OAuth, transcription and memory backend were removed in favor of the offline pipeline. Therefore do NOT import current Omi's Firestore memory_items, graph/assertions, revisions/validity or Pinecone architecture into Memrii. Residual `package:omi` imports are naming/inheritance, not proof those services are active. This is an audio capture/archive/export product, not an implemented post-transcription memory system.

**Capture/storage:** README: device Opus, 16-kHz mono, 20-ms frames → raw circular storage log → BLE closed-segment resumable byte-offset transfer → phone raw .bin → decode/markers/activity timestamps or optional Silero VAD → dated WAV/M4A archive. Phone filesystem and binary metadata sidecars are authoritative; preferences use SharedPreferences and credentials FlutterSecureStorage (https://github.com/simplee-labs/memrii/blob/main/app/lib/backend/preferences.dart#L1-L30). No relational/vector database is needed by or demonstrated in this active archive model; do not assume SQLite just because it is Flutter.

**Concrete schema:** Conversation fields include File, startTime, duration, uploadKey, sessionId, startUptime, subsecond uptime remainder, passthrough/audio-released, forceSynced, capEnded, optional isSilero, tri-state recordedManual, clockCorrected, isCropped and relativeBins[]. Timestamp is parsed from recording_<millis>.wav/.m4a; .meta duration is uint32 little-endian at offset 4, sessionId at 408, uptime at 412; offset 416 starts length-prefixed upload key followed by flags and length-prefixed JSON source-bin references. https://github.com/simplee-labs/memrii/blob/main/app/lib/models/recordings/recordings_models.dart#L9-L220 . These are audio provenance/processing fields, not transcript segments. `IntegrationRecording` normalizes stable id/audioPath/startTime/duration/sessionId/captureMode/clockCorrected/timeUncertain/audioReleased/markers/priority-marker state and deliberately hides BLE/WAL/raw-segment/VAD details from connectors: https://github.com/simplee-labs/memrii/blob/main/app/lib/integrations/integration_recording.dart . Strong modular boundary for YAP.

**Processing rather than memory extraction:** Local Opus decoding and optional ONNX Silero recurrent VAD identify/split playable recordings; timestamps may be corrected from device-session/uptime anchors. Code maintains frame references rather than entire Opus streams in RAM: https://github.com/simplee-labs/memrii/blob/main/app/lib/services/vad_audio_processor.dart#L1-L95 . No native ASR, summarization, fact extraction, semantic search, RAG or graph capability established; README explicitly confirms removal of transcription/memory backend. External destinations may process audio, but their inferred schemas are not Memrii's local schema.

**Privacy/connector boundary:** No Memrii backend/account required. Destinations off by default; normal builds require an explicit per-recording upload/save grant. README lists folder export, HeyPocket (audio + start/duration), unofficial Omi Cloud (Opus in three-minute chunks). Folder provider may itself be network-backed. Optional Omi sidecar uses 4-byte little-endian packet length + 20-ms Opus packet and is only created while a connector requests it; Omi upload cannot reconstruct absent sidecars: https://github.com/simplee-labs/memrii/blob/main/app/lib/services/recording_sidecars.dart . Retention defaults keep-forever; passthrough deletes local audio only after all enabled destinations confirm receipt, leaving metadata. Consent to a connector is not authorization to upload the whole library.

**Maturity/unknowns:** README advertises Android source 0.2.4+15, firmware memrii-fw-3.2.0, signed APK releases and extensive diagnostics/recovery; source tree includes architecture-boundary/reliability tests (not executed). Android/Omi adapter only today, one paired device; other capture adapters are an extension point, not implemented support. Small public project (observed 1 star/0 forks), no independent field reliability established. No local searchable transcript corpus exists in inspected active architecture; service-side transcription availability/retention and any returned-memory ingestion remain unverified and should be treated separately.
